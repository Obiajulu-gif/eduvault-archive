# Deterministic Duplicate Detection and Merge Review Workflow (#961)

## Overview
EduVault provides a deterministic duplicate detection engine and a reviewable, reversible, fully audited merge review workflow across educational content in the marketplace.

The system prevents fragmented creator reputation, accidental double-purchases, duplicate search index clutter, and entitlement loss.

## Architecture

### 1. Deterministic Content Fingerprinting & Scoring
Every material is fingerprinted deterministically using SHA-256 over canonicalized metadata:
- Canonicalized fields: `cid`, `contentHash`, `title`, `description`, `subject`, `category`, `creator`, sorted `tags`, `fileSize`, and `mimeType`.
- Deterministic text normalization: NFKC unicode normalization, lowercasing, non-alphanumeric punctuation stripping, and whitespace collapse.
- Multi-signal similarity detection:
  - `EXACT_CONTENT_HASH`: Exact matching binary/file SHA-256 hash.
  - `IDENTICAL_ASSET_CID`: Exact matching IPFS CID.
  - `IDENTICAL_CREATOR_AND_TITLE`: Exact matching normalized title and creator address.
  - `HIGH_SIMILARITY_METADATA`: Token Jaccard similarity >= configurable threshold (default `0.85`).

### 2. Candidate Detection Ordering
Candidate pairs are deterministically ordered:
- The older record (by `createdAt`, followed by lexical `materialId`) is designated as **Canonical**.
- The newer record is designated as **Duplicate**.
- Pairs are queued into the `duplicate_merge_reviews` collection.

### 3. Review Lifecycle
A duplicate candidate moves through well-defined lifecycle states:
```
[DETECTED] ──> [PENDING_REVIEW] ──> [APPROVED] ──> [MERGED]
     │                                               │
     └──> [REJECTED]                                └──> [REVERSED]
```

- `DETECTED`: Candidate pair generated by detection scan.
- `PENDING_REVIEW`: Review assigned to operator/moderator.
- `APPROVED`: Moderator confirms duplicate relationship.
- `REJECTED`: Moderator rejects duplicate claim (e.g. distinct version/derivative work).
- `MERGED`: Merge executed atomically:
  - Pre-merge snapshot of both items captured into `snapshotBeforeMerge`.
  - Duplicate marked as `status: 'merged'`, `mergedInto: canonicalId`.
  - Canonical `aliases` array updated with `duplicateId`.
  - Audit event `duplicate.merged` recorded.
- `REVERSED`: Merge reversed using pre-merge snapshot:
  - Duplicate restored to previous active status; `mergedInto` cleared.
  - Duplicate ID removed from canonical's `aliases`.
  - Audit event `duplicate.unmerged` recorded.

### 4. Entitlement & Access Preservation
When an absorbed material is merged into a canonical material:
- Buyers who previously purchased the duplicate material retain full, uninterrupted access.
- `getMaterialAccessStatus` and `resolveEntitlement` transparently check aliases and `mergedInto` pointers.
- No re-purchase is required.

## Operational Runbook

### Scanning for Duplicates
Run the detection CLI:
```bash
# Offline dry-run with input fixture:
node scripts/detect-duplicate-materials.mjs --input fixtures/materials.json --threshold 0.85

# Against MongoDB:
MONGODB_URI="mongodb://localhost:27017/eduvault" node scripts/detect-duplicate-materials.mjs --threshold 0.85 --auto-queue
```

### Edge Cases and Failure Modes
1. **False Positives**:
   - If two different materials have high metadata similarity (e.g. "Calculus I - Chapter 1" vs "Calculus I - Chapter 2"):
   - Reviewer sets decision to `REJECTED`. The system will not merge them.
2. **Post-Merge Rollback (Reversal)**:
   - If a merge is disputed by a creator, call `reverseMerge(db, reviewId, actor, reason)`.
   - The stored `snapshotBeforeMerge` restores exact pre-merge state for both records.
3. **Concurrent Purchases during Merge**:
   - Because `findPurchase` and `resolveEntitlement` evaluate both `aliases` and `mergedInto`, in-flight purchases immediately resolve correctly.

### Audit Invariants
Every detection, review decision, merge, and rollback emits an immutable record to `auditLedger`:
- `duplicate.detected`
- `duplicate.review_approved` / `duplicate.review_rejected`
- `duplicate.merged`
- `duplicate.unmerged`
